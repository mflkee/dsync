# Spec Delta

## Purpose

Позволяет по запросу развернуть конкретный проект на конкретной машине через
хаб — с явным выбором force, авторизацией, защитой от дублей и отчётом о
результате, не дожидаясь следующего push-цикла.

## ADDED Requirements

### Requirement: Команда целевого деплоя

CLI SHALL предоставлять команду `dsync deploy --machine <имя>
[--project <проект>] [--force]`. Машина MUST быть описана в конфиге
(`[remote.*]`/`[projects.*] machines`), проект MUST существовать в
статических или авто-обнаруженных проектах. Неизвестная машина или проект
MUST приводить к ошибке без сетевого запроса.

#### Scenario: Неизвестная машина

- **WHEN** пользователь указывает машину, которой нет в конфиге
- **THEN** команда завершается с ненулевым кодом
- **AND** сообщение перечисляет известные машины

#### Scenario: Без проекта

- **WHEN** `--project` не указан
- **THEN** деплой выполняется для всех проектов, где эта машина входит в
  список `machines`

### Requirement: Авторизация и адресация на хабе

Хаб SHALL принимать deploy-запрос только с валидным токеном машины и
выполнять его только для машин и проектов из своего конфига. Запрос MUST
содержать запрашивающую машину, целевую машину, имя проекта (или признак
«все») и флаг force; произвольные команды и пути MUST быть невозможны.

#### Scenario: Чужой токен

- **WHEN** deploy-запрос приходит с неверным токеном
- **THEN** хаб отвечает отказом и не запускает SSH-пулл

#### Scenario: Проект не разрешён

- **WHEN** запрошен проект, которого нет в конфиге хаба
- **THEN** хаб возвращает ошибку с именем проекта и списком доступных

### Requirement: Семантика force

Без `--force` хаб SHALL применять обычную политику: пропускать проект, если
его commit уже развёрнут или не менялся. С `--force` хаб MUST выполнить
pull независимо от change-detection. Офлайн-машина MUST приводить к явной
ошибке «машина офлайн» без серии ретраев.

#### Scenario: Коммит уже развёрнут

- **WHEN** deploy без force для проекта, чей commit уже развёрнут
- **THEN** хаб сообщает «уже развёрнуто» и не выполняет SSH

#### Scenario: Force при том же коммите

- **WHEN** deploy с force для того же проекта
- **THEN** SSH-пулл выполняется заново
- **AND** результат записывается в историю исходов

#### Scenario: Машина офлайн

- **WHEN** последний push машины старше порога online
- **THEN** хаб сразу возвращает ошибку «машина офлайн»
- **AND** SSH-попытки не выполняются

### Requirement: Один деплой на цель одновременно

Хаб SHALL не запускать параллельно два deploy для одной пары
«машина + проект». Повторный запрос во время выполнения MUST возвращать
идентификатор/состояние уже идущей операции или явный конфликт, но не
создавать вторую SSH-сессию.

#### Scenario: Повторный клик

- **WHEN** пользователь дважды запрашивает deploy одной цели
- **THEN** второй запрос получает конфликт с идентификатором текущей задачи
- **AND** вторая SSH-сессия не открывается

### Requirement: Отчёт о результате

Команда SHALL возвращать машину, проект, признак force, время старта и
финиша, число попыток и ошибку при провале. Успешный деплой MUST
обновлять запись о развёрнутом commit; провал MUST сохранять исход с
`ok=false` и текстом ошибки. Код возврата MUST быть 0 только при успехе
всех запрошенных целей.

#### Scenario: Успешный деплой

- **WHEN** SSH-пулл и `post_pull` завершились успешно
- **THEN** команда печатает результат и завершается с кодом 0
- **AND** commit помечается развёрнутым на этой машине

#### Scenario: Ошибка post_pull

- **WHEN** `git pull` прошёл, а `post_pull` упал
- **THEN** результат помечен как failed с stderr
- **AND** commit не считается развёрнутым

### Requirement: Совместимость протокола

Добавление deploy-запроса SHALL поднять версию протокола на 3. Существующие
сообщения push/pull/status/state MUST остаться совместимыми. Клиент,
получивший от хаба «неизвестный запрос», MUST показать понятную ошибку о
необходимости обновить хаб.

#### Scenario: Старый хаб

- **WHEN** новый клиент отправляет deploy старому хабу
- **THEN** клиент завершается с ошибкой «хаб не поддерживает deploy»
- **AND** обычные push/pull продолжают работать

#### Scenario: Старый клиент с новым хабом

- **WHEN** клиент версии 2 выполняет обычный push
- **THEN** хаб принимает его без изменений в поведении

### Requirement: Аудит запросов деплоя

Хаб SHALL писать в лог каждый deploy-запрос: кто запросил, целевая машина,
проект, force, результат и длительность. Секреты и содержимое репозиториев
MUST NOT попадать в запись.

#### Scenario: Разбор инцидента

- **WHEN** проект неожиданно развернулся на машине
- **THEN** в логе хаба видно, какая машина инициировала deploy и когда
- **AND** запись не содержит токена
