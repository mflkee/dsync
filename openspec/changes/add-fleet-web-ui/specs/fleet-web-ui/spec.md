# Spec Delta

## Purpose

Локальная веб-панель для обзора и управления флотом dsync: здоровье хаба,
машины, проекты, состояние tmux/opencode и безопасные действия — без доступа
из сети и без секретов в браузере.

## ADDED Requirements

### Requirement: Панель доступна только локально

Сервер панели SHALL по умолчанию слушать только loopback-адрес
(`127.0.0.1`). Запуск с привязкой к не-loopback адресу MUST требовать явно
заданный токен доступа и MUST завершаться ошибкой, если токен не задан.
Токены хаба, приватные ключи и payload'ы состояния MUST NOT передаваться в
браузер.

#### Scenario: Обычный запуск

- **WHEN** панель запущена с настройками по умолчанию
- **THEN** она принимает соединения только с `127.0.0.1`
- **AND** ответы API не содержат hub-токенов и содержимого state-payload'ов

#### Scenario: Попытка выставить в сеть без токена

- **WHEN** в конфигурации задан не-loopback адрес, а токен пуст
- **THEN** сервер не стартует и пишет понятную ошибку в лог

### Requirement: Dashboard показывает здоровье флота

Главный экран SHALL показывать версию хаба и его доступность, число машин
online/offline, машины с дрейфом версии клиента, число упавших pull'ов и
элементов state в dead-letter, а также время последнего успешного
обновления данных.

#### Scenario: Хаб доступен, есть отставания

- **WHEN** `status --json` вернул две машины, у одной версия отличается от
  хаба, у другой упал pull проекта
- **THEN** Dashboard показывает счётчики online/offline, дрейф версий и
  упавший pull с именем машины и проекта

#### Scenario: Хаб недоступен

- **WHEN** BFF не может получить `status --json`
- **THEN** Dashboard показывает баннер «хаб недоступен» с текстом ошибки
- **AND** не подставляет нули вместо реальных данных

### Requirement: Экран машин с деталями

Экран Machines SHALL показывать список машин с признаком online, временем
последнего push, версией клиента и сводкой pull'ов. Детали машины MUST
показывать исход каждого проекта (ok/failed, число попыток, время, текст
ошибки) и доступные для неё действия.

#### Scenario: Машина офлайн

- **WHEN** последний push машины старше порога online
- **THEN** машина отображается как offline с относительным временем
- **AND** действия, требующие связи, недоступны с объяснением

#### Scenario: Ошибка pull проекта

- **WHEN** у машины есть pull с `ok=false`
- **THEN** в деталях виден проект, число попыток и полный текст ошибки
- **AND** длинный текст можно развернуть, вёрстка не ломается

### Requirement: Матрица проектов

Экран Projects SHALL показывать состояние «машина × проект»: последний
исход, попытки, время и ошибку, с фильтром «только проблемы». Пустое
состояние MUST объяснять, что проектов нет, а не показывать пустую таблицу.

#### Scenario: Фильтр проблем

- **WHEN** пользователь включает «только проблемы»
- **THEN** остаются строки с упавшими pull'ами или отсутствующим деплоем
- **AND** счётчик показывает число скрытых строк

#### Scenario: Нет проектов

- **WHEN** хаб не вернул ни одного проекта
- **THEN** показывается пустое состояние с подсказкой проверить конфиг

### Requirement: Экран State и повтор dead-letter

Экран State SHALL показывать сводку каналов tmux/opencode и локальные
failing/dead-letter элементы с ключом, попытками и причиной. Повтор
элемента MUST быть доступен по одному и для всех сразу, с подтверждением,
и MUST явно указывать, что действие выполняется на машине, где запущена
панель.

#### Scenario: Повтор одного элемента

- **WHEN** пользователь подтверждает retry для `tmux:notebook`
- **THEN** создаётся задача `dsync state retry tmux:notebook`
- **AND** после успеха элемент исчезает из dead-letter при следующем
  обновлении

#### Scenario: Панель не на той машине

- **WHEN** панель запущена на машине без нужного state-элемента
- **THEN** экран показывает данные этой машины и явную подпись, что это
  локальный state, а не флота

### Requirement: Doctor запускается по требованию

Экран Doctor SHALL запускать `doctor --json` по кнопке, показывать проверки
со статусами ok/warn/fail, версии клиента и хаба, время запуска и текст
ошибок. Предыдущий результат MUST оставаться видимым до нового запуска.

#### Scenario: Проверка с провалом

- **WHEN** doctor вернул проверку со статусом `fail`
- **THEN** она выделена, раскрыта и видна причина
- **AND** запуск помечен как неуспешный

#### Scenario: Повторный запуск

- **WHEN** пользователь запускает doctor второй раз
- **THEN** старый результат заменяется новым только после завершения
- **AND** во время выполнения виден индикатор

### Requirement: Действия выполняются как фоновые задачи

Любое изменяющее действие (push, pull, deploy, state retry, doctor) SHALL
создавать задачу и немедленно возвращать её идентификатор. Статус задачи
MUST опрашиваться отдельным запросом и содержать состояние
`queued|running|ok|failed`, время старта/финиша, код возврата и последние
строки вывода без секретов.

#### Scenario: Долгий deploy

- **WHEN** deploy длится дольше таймаута обычного HTTP-запроса
- **THEN** браузер продолжает опрос и получает `running`
- **AND** по завершении получает `ok` или `failed` с причиной

#### Scenario: Дубликат действия

- **WHEN** для той же машины и проекта уже выполняется задача
- **THEN** API возвращает конфликт с идентификатором текущей задачи
- **AND** вторая задача не запускается

### Requirement: Только разрешённые действия

Панель SHALL позволять только фиксированный набор действий: push, pull,
deploy, state retry, doctor. Любые другие команды, произвольный shell и
редактирование конфигурации MUST быть недоступны. Перед изменяющим
действием MUST показываться подтверждение с целью и последствиями.

#### Scenario: Попытка неизвестного действия

- **WHEN** клиент отправляет действие, которого нет в allowlist
- **THEN** API отвечает 400 и ничего не выполняет

#### Scenario: Подтверждение deploy

- **WHEN** пользователь нажимает «Развернуть» на машине и проекте
- **THEN** показывается подтверждение с машиной, проектом и признаком force
- **AND** задача создаётся только после подтверждения

### Requirement: Журнал действий

Панель SHALL вести аудит-журнал изменяющих действий: время, действие,
машина/проект, инициатор (локальный пользователь), результат и текст
ошибки. Журнал MUST быть доступен на экране Activity и MUST NOT содержать
секреты, токены и payload'ы состояния.

#### Scenario: Действие завершилось ошибкой

- **WHEN** deploy упал
- **THEN** в Activity есть запись с действием, целью, временем и ошибкой
- **AND** секреты отсутствуют в записи

#### Scenario: Перезапуск панели

- **WHEN** сервер панели перезапущен
- **THEN** ранее записанный журнал сохраняется и доступен

### Requirement: Обновление данных и устаревание

Экраны только для чтения SHALL обновляться автоматически с настраиваемым
интервалом (по умолчанию 10 секунд), паузой при скрытой вкладке и ручной
кнопкой обновления. Для каждого снимка MUST отображаться время получения,
а данные старше трёх интервалов — помечаться как устаревшие.

#### Scenario: Вкладка скрыта

- **WHEN** вкладка браузера неактивна
- **THEN** автоматические запросы приостанавливаются
- **AND** при возврате данные обновляются сразу

#### Scenario: Данные устарели

- **WHEN** последнее успешное обновление старше трёх интервалов
- **THEN** интерфейс показывает пометку «данные устарели» с временем

### Requirement: Совместимость версий и понятные ошибки

Если JSON-схема CLI новее поддерживаемой или хаб не умеет deploy, панель
SHALL показать объяснение и отключить несовместимые действия, а не падать.
Ошибки команд MUST отображаться с кодом возврата и stderr.

#### Scenario: Старый хаб

- **WHEN** хаб отвечает «unknown deploy request»
- **THEN** кнопка deploy отключена с подсказкой обновить хаб
- **AND** остальные экраны продолжают работать

#### Scenario: Неподдерживаемая schema_version

- **WHEN** `status --json` вернул `schema_version` больше поддерживаемого
- **THEN** показывается баннер о несовместимости
- **AND** данные не интерпретируются частично

### Requirement: Русский интерфейс и доступность

Интерфейс SHALL быть на русском языке, с клавиатурной навигацией,
подписями для иконок и достаточным контрастом. Длинные технические строки
(пути, ошибки) MUST переноситься или обрезаться с возможностью раскрытия.

#### Scenario: Навигация с клавиатуры

- **WHEN** пользователь проходит по интерфейсу только с клавиатуры
- **THEN** все интерактивные элементы достижимы, фокус видим

#### Scenario: Длинная ошибка SSH

- **WHEN** pull вернул многострочную ошибку
- **THEN** в таблице она обрезана, а в деталях раскрывается полностью
